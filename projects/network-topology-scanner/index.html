Network Topology Scanner + self-hosted DevOps platform

A Python network scanner, and the platform that builds, deploys, monitors and backs it up: Terraform, Kubernetes, Jenkins, AWS through OIDC, Prometheus, Grafana and Loki.

Type
Personal open-source project
Date
2026 — Present
Role
Sole author
Source
GitHub

01Technical summary

The tool scans a network with Nmap (and the routers over SNMP), classifies devices, flags risky open ports, keeps a history in SQLite and draws the topology. It is published on PyPI and as a multi-arch image on GHCR.

Around it I built the platform that runs it every night in my homelab, in eight phases, each with a runbook: a Kubernetes VM created with Terraform, a Helm chart, continuous deployment with Jenkins, AWS resources managed by GitHub Actions, and monitoring and logs with alerts. It is a one-node homelab, not a production system, and the decisions are sized for that.

02Architecture

03My contribution

Designed, built and documented everything: the tool, its tests and CI, the infrastructure, the pipeline and the monitoring, and failure rehearsals.

04Implementation

  • CI and releases — GitHub Actions runs ruff, 600+ pytest tests, a Trivy scan of the image, terraform test, helm lint and promtool. A version tag publishes to PyPI (trusted publishing) and GHCR (amd64 + arm64).
  • Infrastructure as code — Terraform creates the k3s VM on Proxmox with cloud-init, with its state in S3. AWS resources (S3, SNS, IAM) are applied by GitHub Actions through OIDC: no stored keys, read-only plans on pull requests, apply behind a manual approval.
  • Continuous deployment — Jenkins runs inside the cluster and polls GitHub, so nothing reaches into the LAN. Each release goes through helm upgrade and helm test; on failure it rolls back to the exact previous revision and sends an email. Rehearsed by forcing failures.
  • Observability — Prometheus with alert rules tested by promtool, a Grafana dashboard, logs in Loki collected by Alloy, alerts on Telegram, and an external watchdog (healthchecks.io) that fires if the monitoring itself goes down.
  • Supply chain and least privilege — third-party actions pinned by commit SHA and third-party images by digest, enforced by tests; nmap runs without root using file capabilities.
  • Backups — reports and a versioned copy of the scan history go to S3; the restore was tested by deleting the data volume on purpose.

05Result / output

A scan that runs every night without anyone touching it, an email only when the network changes in a way worth a look, and a platform that can be rebuilt from the repository.
